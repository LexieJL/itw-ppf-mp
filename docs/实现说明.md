# 实现说明

从 README 移过来的详细记录：根据 ITW 反馈做的改动、按默认做法待确认的事项、接后端时要换掉的地方。

## 根据 ITW 反馈已改的地方

1. 角色确认为游客、普通会员、认证会员（经销商及客户）、ITW员工，与原来一致；注册页认证会员的说明加了“适用于经销商及客户”。
2. 权限按图例三档：“销售用ACH源文件”从“仅员工”改为认证会员即可查看。
3. 表单先按现有 UI 开发：去掉了之前自己加的“资质文件上传”。
4. 可视化配置：首页 Banner 和模块改为读后台配置（顺序、显示隐藏、标题、跳转、权限），新增通用页面 pages/custom，运营可用预制控件新增页面、配置按钮跳转，不用改代码、不用重新提审。新增控件类型仍需开发。
5. 首页第二屏“更多模块”：加了“常见问题库”和“活动专题”两个示例。
6. 七大行业及细分领域按 Jiayuan 提供的表格更新（utils/mock.js 的 INDUSTRIES）。
7. 测试阶段注册字段可以全部留空提交（pages/register/register.js 的 ALLOW_EMPTY，上线前改为 false）；填了的手机号、邮箱、验证码仍检查格式。
8. 测试阶段提交认证后直接成为认证会员并提示“认证成功”（pages/register/register.js 的 AUTO_CERTIFY，上线前改为 false 恢复审核流程）。
9. 产品库换成 ITW 产品表（【4国语言翻译】模版-小程序用2.xlsx）的真实数据：
   - 左侧品牌按产品数排序，含中文名；没有产品的品牌（Rain-x、Korrobond、CFO、CFR）排在最后，只显示介绍。
   - 右侧上方是该品牌的“产品系列”，代替原来的“聚合物/流体”。左上角不放标题，左侧栏直接通到顶部（应用库、知识库同样处理）。
   - 品牌 logo 和中文介绍放在右侧顶部卡片，可展开。
   - CN 表 704 行按“品牌 + 产品名”合并成 528 个产品，同一产品的不同代码和包装规格在详情页列成表；产品概述优先用“改变的产品概述”。
   - 品牌写法统一（PLEXUS/Plexus、KRAFFT/Krafft、Wynns/Wynn's 等）；有一行品牌留空，按上一行算作 Schnee-Morehead。
10. “市场对应的资料”里的手册挂到知识库“培训文档”对应行业下（每个细分领域都显示，标“行业通用”），两条【视频】放进“培训视频”。

## 仍按默认做法、待确认的

1. **产品分类**：按产品表做成 品牌 > 产品系列 > 产品。
2. **多语言**：表格名叫“4国语言”，但目前只有中文。先只做中文；数据按字段存放，拿到英文等译文后加一个语言切换即可，不用改页面结构。
3. **产品图**：表里只有文件名（如 30000.jpg），图片还没提供，先用占位图。
4. **“可删除（不在手册中）”的产品**：暂时保留显示（按产品算 70 个），等 ITW 确认是否下架。
5. **市场与七大行业的对应**：交通运输行业→交通、电子行业→电子、汽车后市场→汽车后市场、工业维修与保养→重工、工业清洗与润滑→流体、新能源→风能、船舶行业→船舶。产品详情页直接显示表里的市场和领域，产品暂未和应用库的细分领域关联。
6. **缺资料的品牌**：Schnee-Morehead、American Safety、Korroflex 在产品表里有产品但没有品牌介绍和 logo；Chockfast 没有单独 logo，借用 CFO 的；CFR、DYKEM 没有介绍；Corium、Magna、ZetaLube、Epocast、DYKEM 没有中文名。
7. **认证审核（上线后）**：提交后先保持普通会员并显示“审核中”，销售在 CRM 中确认后升级。
8. **游客点底部标签**：游客点“应用库”“产品库”显示模糊页面和注册提示。
9. **工业电商**：进入商城页（`utils/cms.js` 的 `PAGES.mall`），列出工业品商城（京东）和汽车养护品商城（天猫、京东）。外部网站不能在小程序内打开，点击后复制链接，提示用户到浏览器访问。
   - **官网与招聘**：放在会员中心「关于 ITW」（`utils/cms.js` 的 `LINKS`、`ABOUT`）。官网用 web-view 在小程序内打开，需在小程序后台把 www.itwppfasia.com 配置为业务域名；招聘为 51job 网站，复制链接。
   - **Logo 与品牌色**：ITW Logo 在 `images/itw-logo.png`，用于会员中心公众号卡片、「关于 ITW」和注册页顶部；品牌色按 Logo 规范改为 PANTONE 1955C（#8A1538）。
10. **底部标签栏**：微信原生标签栏只在四个标签页显示，二级页面靠返回；要每页都显示需改成自定义底栏。
11. **公众号**：推文用 web-view 打开，需要小程序关联公众号；“关注”按钮正式版用 official-account 组件。

## 接后端时要换掉的地方

- `utils/auth.js`、`utils/fav.js`：本地缓存换成 CloudBase 数据库和云函数。
- `utils/mock.js`：换成从 CloudBase 读取的内容。
- `utils/catalog.js`（约 330KB）：上线前把品牌和产品导入 CloudBase 数据库，前端按需读取，避免占用代码包体积。
- 各表单 `submit()`：调用云函数保存，并按第19页的流程同步 CRM。
- `.ph` 占位块：换成 `image` / `video`（云存储地址）；PDF 用 `wx.downloadFile` + `wx.openDocument`。
