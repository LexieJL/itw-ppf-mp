# ITW PPF 小程序后端接口文档

初稿：2026-10-03 · Jiayuan Li；本次同步：2026-11-02

## 1. 说明

本文档是前端（Jiayuan）交给后端（Ruby）的接口约定，内容从当前小程序代码（本仓库）整理而来。原生主要使用本地数据；网页已读取部分 CloudBase 应用/资源。本文的云函数、提交、审核、通知为待实现的接口约定，不代表已上线。接入时仍需完成数据适配、身份校验和联调。

配套材料：[《ITW PPF 小程序产品开发文档》](小程序产品开发文档.md)（页面、权限、字段字典）、[可点击原型](https://lexiejl.github.io/itw-ppf-mp/)、产品表 xlsx 与 tools/gen\_catalog.py。

### 1.2 调用约定（建议）

- 前端统一用 `wx.cloud.callFunction` 调用云函数，不在前端直接读数据库。原因是大部分内容要按用户角色过滤，校验必须放在后端。
- 建议按模块分几个云函数，用 `action` 区分操作，例如 `callFunction({ name: 'product', data: { action: 'list', brandId, series } })`。
- 统一返回格式：`{ code: 0, data: {...}, msg: '' }`。
- 列表接口统一分页：入参 `page`（从 1 开始）、`pageSize`（默认 20）；出参 `{ list: [], total }`。
- 时间字段统一用毫秒时间戳。

### 1.3 错误码

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 0 | 成功 | 正常展示 |
| 400 | 参数错误 | 提示 msg |
| 401 | 未注册（游客） | 显示遮罩，引导注册 |
| 403 | 已注册但权限不够 | 显示遮罩，引导认证；data 里带 `need: 'certified'`，以及 `certStatus`（审核中时提示等待） |
| 404 | 内容不存在或已下架 | 提示并返回上一页 |
| 500 | 服务端错误 | 提示稍后重试 |

### 1.4 登录与身份

- 不需要单独的 token：云函数里用 `cloud.getWXContext().OPENID` 识别用户。
- 小程序启动时调用 `user.get` 拿到当前用户；查不到记录即视为游客（role = guest）。前端把结果缓存在本地，用来决定是否显示遮罩，但最终以后端校验为准。
- 用户角色、认证状态只能由后端修改（注册、审核通过、员工邮箱验证），前端提交的 role 字段只作为申请类型。
- 现在前端的身份逻辑在 utils/auth.js，接入后 `getUser()` 改为读 `user.get` 的结果。

## 4. 表单提交

前端已做格式校验，后端请按同样规则再校验一次。通用规则：手机号 `^1\d{10}$`；邮箱 `^\S+@\S+\.\S+$`；验证码 6 位数字。所有文本去掉首尾空格。

### 4.1 注册 user.register（pages/register）

| 字段 | 含义 | 普通会员 member | 认证会员 certified | 员工 staff |
| --- | --- | --- | --- | --- |
| name | 姓名 | 必填 | 必填 | 必填 |
| phone | 手机号 | 必填 | 必填 | 必填 |
| smsCode | 短信验证码 | 必填 | 必填 | — |
| company | 公司名称 | 选填 | 必填 | — |
| title | 职位 | 选填 | 必填 | — |
| brands | 已代理品牌 / 主营产品 | — | 必填 | — |
| industrySelections | 关注细分行业（至少1个有效配对，可跨市场多选） | 必填 | 必填 | — |
| email | 邮箱 | 必填 | 必填 | 必填（ITW 企业邮箱） |
| isDealer | 是否已是 ITW PPF 经销商（是 / 否） | — | 必填 | — |
| dept | 部门 | — | — | 必填 |
| emailCode | 邮箱验证码 | — | — | 必填 |

`industrySelections` 为 `[{marketId, marketName, segmentId, segmentName}]`。服务端以ID校验父子关系、去重并回填标准名称，不信任客户端名称。原生编辑时使用细分ID数组，保存资料时展开完整配对；旧 industries 仅作兼容展示，不能推断用户选择了该市场全部细分行业。

处理结果：

- member：校验短信码后直接写入 users，role = member。
- certified：写入 users（role = member，certStatus = pending），同时新建一条 cert\_applications 并同步到 CRM，由销售审核（见第 6 节）。
- staff：校验邮箱验证码且域名为 ITW 企业邮箱后，role = staff。
- 已是普通会员的用户再提交认证：更新资料、新建认证申请，不改 role。

## 5. 权限校验规则

角色等级与内容等级一一对应，角色等级 ≥ 内容等级即可访问（与前端 utils/auth.js 的 `can()` 相同）。

| 角色 role | 等级 | 可访问的 access |
| --- | --- | --- |
| guest 游客 | 0 | public |
| member 普通会员 | 1 | public、registered |
| certified 认证会员 | 2 | public、registered、certified |
| staff ITW员工 | 3 | 全部 |

ITW 已确认没有员工专属内容，运营后台设置 access 时只提供 public / registered / certified 三个选项。

### 5.1 后端怎么校验

1. 每个云函数入口先用 OPENID 查 users 得到 role（查不到 = guest）。不要信任前端传来的 role。
2. 接口级权限（第 3 节「权限」列）不满足时，直接返回 401 / 403，不返回数据。
3. 详情接口按内容access判断。应用详情不满足时仅返回明确公开的标题、图片、摘要、面包屑和权限提示，用于局部预览；其他详情沿用403遮罩规则。不得返回完整正文和受限文件URL。
4. 列表和搜索接口不过滤掉无权限的条目，而是标 `locked: true`，让用户知道有这个内容、需要认证。
5. PDF、视频的临时链接只在权限校验通过后由云函数生成（`cloud.getTempFileURL`）；云存储里的认证级文件设为仅管理端可读，不要公开读。
6. 数据库安全规则：内容类集合前端不可直接读写；users、favorites 等用户类集合只允许通过云函数修改，防止用户自己改 role。

### 5.2 前端现在各页的权限（供核对）

| 页面 | 前端判断 |
| --- | --- |
| 首页、工业电商、搜索、活动专题、应用列表及应用公开摘要 | public |
| 产品库（列表 + 详情）、知识库入口、收藏、需求咨询、成为经销商、常见问题库 | registered |
| 应用详情（含销售用 ACH 源文件）、公司介绍、产品培训的视频和文档 | certified |

认证申请审核中的用户（certStatus = pending）仍按普通会员处理，前端会把遮罩文案改为「认证申请审核中」。

## 6. 状态流转与订阅消息

以下为后续通知设计，当前前端没有调用订阅授权或发送通知。申请人结果通知与指定销售接收业务机会是两条不同流程，不能把申请人的授权当作销售的接收资格。微信具体渠道、账号能力、模板及接收条件需后端和ITW核实后确定，不能承诺无条件送达。

### 6.1 认证申请

| 状态 | 触发 | users 变化 | 订阅消息 |
| --- | --- | --- | --- |
| pending 审核中 | 用户提交认证表单 | role = member，certStatus = pending | 无 |
| approved 通过 | 销售在 CRM 或运营后台点「通过」 | role = certified，certStatus = '' | 「审核结果通知」：结果 = 已通过，提示可查看专属内容 |
| rejected 驳回 | 点「驳回」并填写原因 | role = member，certStatus = rejected | 「审核结果通知」：结果 = 未通过 + 原因 |

驳回后用户可以重新提交，生成新的 cert\_applications 记录。前端会员中心目前只处理了 pending，rejected 的提示文案由 Jiayuan 补。

### 6.2 需求咨询、经销商申请、FAQ 提问

| 记录 | 状态 | 说明 | 订阅消息（建议） |
| --- | --- | --- | --- |
| inquiries | new → assigned → contacted → closed | 保存后按 marketId + segmentId 查找负责人并分派，同步 CRM；通知发送单独记录状态 | 销售标记「已联系」时发「咨询受理通知」 |
| dealer\_applications | new → reviewing → approved / rejected | 运营或渠道经理处理 | 有结果时发「申请结果通知」 |
| faq\_questions | pending → answered → published | 运营回答后可选择发布到问题库（复制为一条 faqs） | 回答后发「问题回复通知」 |

如果后续做「我的申请」页面（见《小程序改进建议》第 2 条），前端会需要一个 `form.mine` 接口，返回当前用户的以上记录和状态。

## 7. 业务规则

### 7.1 行业通用资料

docs 和 videos 里 `subId` 为空的条目是「行业通用」资料（来自产品表「市场对应的资料」）。查某个细分领域时，返回：`subId = 该细分领域` 或 `industryId = 该行业 且 subId = ''`。前端会把后者标为「行业通用」，面包屑显示行业名。对应前端代码：mock.js 的 `inSub()`。

### 7.2 产品合并与 id

- 产品表 CN 表一行是一个代码（SKU）。同一品牌 + 同一产品名的多行合并为一个产品，代码和包装规格放进 skus。704 行合并后是 528 个产品、669 个 SKU。
- 品牌写法已统一（PLEXUS/Plexus、KRAFFT/Krafft、Wynns/Wynn's 等）；品牌为空的一行按上一行算作 Schnee-Morehead。合并和统一规则见 tools/gen\_catalog.py。
- inBook：「是」在手册中，「可删除」不在手册中（是否下架待 ITW 确认，目前照常显示），空为未标注。isNew 为新增行，前端显示「新品」标签。
- **id 要稳定**：前端现在的 p1、p2… 是按表格行顺序生成的，活动专题页引用了 p131 / p132 / p1 / p29，收藏和转发链接也存了 id。后端入库后，重新导入产品表时请按「品牌 + 产品名」匹配已有产品并更新，不要重新编号。

### 7.3 排序

| 列表 | 排序 |
| --- | --- |
| 品牌 | 按产品数从多到少；没有产品的品牌（Rain-x、Korrobond、CFO、CFR）排在最后，只显示介绍。后台可用 sort 覆盖 |
| 产品系列 | 仅返回有效系列，不返回“全部”；按首次出现顺序，默认首项，切换品牌时重置 |
| 产品 | 按产品表行顺序（即 sort） |
| 行业通用资料 | 排在该细分领域自己的资料前面 |
| 收藏 | 按收藏时间倒序 |
| 其他内容 | 按 sort，再按 createdAt 倒序 |

### 7.4 搜索匹配范围

全局搜索不区分大小写，按空白分词后所有词都须命中；“新能源电池”“新能源动力电池”“新能源汽车动力电池”按同义词匹配。前端当前搜索已加载数据，服务端索引与分页尚待实现。

| 分组 | 匹配范围 | 点击目标 |
| --- | --- | --- |
| 产品 | 名称、品牌中英文名、系列、SKU、概述、使用方法、市场和领域 | 产品详情 |
| 应用方案 | 应用名、简介、页面正文、所属市场和细分行业 | 应用详情 |
| 推文 | 已加载的标题、简介/正文、关联行业 | 所属应用详情，再打开推文 |
| 视频 | 标题、类型、简介/正文、关联行业 | 培训视频详情或所属应用详情 |
| 文档 | 标题、类型、简介/页面正文、关联行业 | 文档详情或所属应用详情 |
| 知识库 | 公司介绍标题、简介、正文，常见问题分类/问题/答案 | 对应知识库页面 |

不抓取外部推文正文，不搜索 PDF/Word 等附件内部文字和视频内部内容。缺少字段不能承诺可被搜索。服务端索引必须在返回正文、文件URL前校验权限；资源与所属页面取更严格权限。

### 7.5 收藏

- 以 `_openid + type + id` 唯一，重复收藏即取消。
- 应用详情里的「销售用 ACH 源文件」和普通文档是同一条 docs，前端给前者的收藏 id 加了 `-s` 后缀、url 加 `&sales=1` 来区分。
- 公司介绍文章收藏时 type 为 doc。
- 内容下架或用户失去权限后，收藏仍保留，点开时由详情接口返回 404 / 403。

### 9.2 产品视频与补充视频

产品详情返回两个数组：`videos`（产品视频）与 `additionalVideos`（原正文咨询卡片位置的更多视频资料）。单项 `{id, title, src, poster, access, visible}`，顺序按后台排序返回。src 为完成访问授权后的可播放URL，poster 为可选封面。后台负责上传、资源与产品关联、排序、隐藏和链接有效期。

前端支持多条、权限过滤、隐藏项过滤及按URL去重；同一地址已在主视频出现时不在补充区域重复。主视频无数据则隐藏；更多视频资料无数据时保留“暂无更多视频资料”。不在用户端增加上传入口。ACH维持现状，本期不拆分或重做。
